What this tests, and what it doesn't

The inputs are gUFO Turtle files. These results show that OntoGraph admits them, stores them as typed candidates and regenerates them with no semantic loss, and that its output gives the same SHACL and OWL verdicts as the originals. They don't yet show how OntoGraph projects an OntoUML model into gUFO. The recorded run is from 9 October 2026, and the checks were reproduced by automated agents. No human ontologist has reviewed the results yet. See how this was checked.

:Manager is declared a gufo:Kind but specialises :Employee, a gufo:Role. Both violations are on that rdfs:subClassOf. First, a Kind can't specialise a type that already provides an identity principle. Second, a rigid type can't specialise an anti-rigid one.

02 / Coverage

Coverage of the areas you named

You suggested relators, qualities, events, situations and higher-order types. Here is what the examples cover today, and what they don't.

Valid and invalid cases for each area
AreaCovered byValid casesInvalid casesNot covered yet
RelatorsExample 410No negative case, for example a relator missing a mediated party, or mediating a Kind where a Role is expected. Derived material relations are preserved, but nothing is inferred.

The main gap is negative cases

Both invalid cases are the pitfalls that ship with the upstream examples. For relators, qualities, events and situations, OntoGraph has only been tested on valid input. A small set of invalid cases in those areas, with the violations you'd expect, would be the most useful next test.

03 / Check it yourself

Re-run the checks in one command

The bundle contains the nine upstream files, OntoGraph's output for each, gUFO and gufoshapes at the pinned commits, the expected results and a short Python script. It doesn't need OntoGraph.

python -m pip install -r requirements.txt
python check.py

The script checks every file hash, checks that each output is isomorphic to its upstream input, and runs pySHACL the way the gUFO examples' own test suite does: gufo.ttl plus the example, no inference, with advanced features on. It then compares each violation with the recorded run. Its summary reads:

Assertions preserved: 808/808
Valid examples conforming: 7/7
Invalid examples flagged: 01-endurant-types-invalid = 2 violations, 07-higher-order-types-invalid = 5 violations
All expectations reproduced.

Not covered by the bundle

What needs more than Python

The bundle doesn't include OWL 2 DL reasoning. The recorded run used Pellet, and the examples' own harness (owlready2 + Pellet) can repeat it. Regenerating the outputs needs the OntoGraph runtime, which isn't public yet. The bundle checks the published outputs, not the pipeline that produced them.

04 / How this was checked

Who checked what

  • Recorded run (9 October 2026). OntoGraph runtime at source commit 1c3e2f7 ran all nine files twice, with 146 operations each time. Both runs produced byte-identical candidates, admissions, regenerated graphs and shapes. OWL used Pellet, and SHACL used Apache Jena with gufoshapes.
  • Reproduction. A separate run repeated the complete suite with the same results. That run and the review records on this site were done by automated AI agents, separate from the agents that produced the work. Their records list no open findings.
  • Portable re-check (24 November 2026). The bundle above reproduced the SHACL and preservation results with a second toolchain, RDFLib and pySHACL.
  • Not yet done. No human ontologist has reviewed these results or the modelling below.

05 / Questions

Where your view would help most

  1. Time-qualified grounding. When a role holds only while a relator exists, such as a researcher during an appointment, should a gUFO projection express that through the relator's own begin and end points, through situations, or through something else? What should a query asking "who held the role at time t" be allowed to conclude?
  2. Identity and dependence in partial snapshots. If a graph is a partial snapshot, for example an appointment whose organisation simply isn't recorded, should a UFO-grounded system report a violation (closed world) or an unknown participant (open world)? Does that choice change how identity should be carried across snapshots?
  3. Difference from the existing OntoUML-to-gUFO export. The OntoUML server and the Visual Paradigm plugin already export OntoUML models to gUFO. Where, if anywhere, should OntoGraph's projection behave differently? Which test cases would show that it stays faithful?

Related work

This work builds on UFO (Guizzardi, Ontological Foundations for Structural Conceptual Models, 2005; Guizzardi et al., UFO: Unified Foundational Ontology, Applied Ontology, 2022) and on OntoUML as the language for UFO-compliant models. The target is gUFO (Almeida, Guizzardi, Sales and Fonseca, gUFO: A Gentle Foundational Ontology for Semantic Web Knowledge Graphs, 2026), validated with gufoshapes. The closest existing tool is the OntoUML-to-gUFO transformation in the OntoUML server, which the Visual Paradigm plugin uses for "Export to gUFO". OntoGraph doesn't replace it. OntoGraph aims to keep the richer model as the authority and to carry identities and provenance into the projected views.

06 / OntoGraph's own worked case

Research appointments: modelling under revision

Separately from your examples, we built a small case of our own about people, organisations and research appointments, to test how OntoGraph keeps identities connected across views. Its evidence is recorded, but the model has known problems, and we'll revise it before asking for feedback on it.

Known issues
  • The «role» Researcher isn't connected to any mediation. Appointment mediates Person and Organization directly, whereas gUFO's relators example mediates the roles Employee and Employer.
  • Time uses a custom comp:begin/comp:end pair instead of gUFO's own properties, such as gufo:hasBeginPointInXSDDateTimeStamp.
  • The appointment data is contrived: intervals of two to three hours, a leap day and a +14:00 offset, chosen to test edge cases rather than to look realistic.
  • The Mass quality and the Seminar event are in the model without any explanation of why they are there.
  • The generated graph types Appointment and Mass as gufo:EndurantType, as subclasses of gufo:Relator and gufo:Quality. That choice hasn't been justified.
