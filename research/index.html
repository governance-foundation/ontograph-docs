The published Turtle at gUFO commit f412254 is a comparison target only. It was not the input to the projection. Instance data is an OntoGraph-specific file, because OntoUML has no instance level.

What this tests, and what it doesn't

These results show a genuine OntoUML-to-gUFO projection: OntoUML JSON, then UFO rules, then gUFO. They do not show that OntoGraph merely admits and regenerates the upstream Turtle. That earlier check, from 9 October 2026, preserved 808 of 808 assertions and is documented separately in the Turtle round-trip section. It is not the headline result on this page. No human ontologist has reviewed the models or these results yet. See how this was checked.

02 / Differences

Differences from the upstream Turtle

Because the models were authored from the example prose, the projected gUFO is not identical to the published Turtle. Every unmatched triple in the retained run was classified. The ordinary categories are annotations and ontology headers, individuals that appear only in the Turtle and not in the prose, extra axioms that OntoGraph derives from UFO, equivalent OWL forms, and stereotypes that OntoUML requires and upstream sometimes leaves untyped. The genuine content differences are recorded in reviewed-differences.v1.json. They have had a self-review only. NEMO review is still pending, and the following are offered as questions, not as corrections of the upstream examples.

  1. Invalid 07, encoding of the pitfall. OntoUML has no way to add a member to a generalization set while omitting only the OWL disjointness, so the pitfall is modelled as a second, non-disjoint generalization set {Tiger} with the same categorizer. That set projects as gufo:categorizes in addition to the existing gufo:partitions. Is that a faithful encoding of the invalid-07 pitfall?
  2. Example 05, MatchParticipation. OntoUML has no instance level and cannot type an individual by a gUFO class directly, so the reified participation in the prose is modelled as an «event» class MatchParticipation, of which JordanLeeParticipationInFinal is an instance. Pellet then derives the upstream typing as a gufo:Participation. Is that an acceptable OntoUML encoding?
  3. Example 05, range of :participatedInMatch. In the upstream Turtle, :participatedInMatch has range :Match and is used to link :JordanLee to :JordanLeeParticipationInFinal. Under OWL that would also classify the participation as a Match. OntoGraph instead projects gufo:participatedIn from Player to MatchParticipation. Was the upstream range intended?

A further reviewed difference in example 06 is not a modelling disagreement: the prose names the sepsis alert but does not state the time it fired, so the begin timestamp that appears only in the upstream Turtle was omitted.

No class or instance diagrams are published in this edition. The OntoUML models are in JSON, with the projected Turtle beside them.

03 / Check it yourself

Re-run the checks in one command

The bundle contains the nine OntoUML models and instance files, OntoGraph's gUFO output for each, the upstream Turtle for comparison, classified diffs, recorded findings and oracles, gUFO and gufoshapes at the pinned commit, the expected results and a short Python script. It doesn't need OntoGraph.

python -m pip install -r requirements.txt
python check.py

The script checks every file hash, checks the recorded UFO-rule findings and classified diff counts, and runs pySHACL the way the gUFO examples' own test suite does: gufo.ttl plus the output, no inference, with advanced features on. It then compares each violation with the recorded run. It also checks the two OntoGraph extensions of example 05, which are not acceptance cases. Its summary reads:

Valid examples with no UFO-rule findings and conforming gufoshapes: 7/7
Invalid examples flagged: invalid-01-endurant-types = 2 rule finding(s), 2 gufoshapes violation(s), invalid-07-higher-order-types = 1 rule finding(s), 6 gufoshapes violation(s)
All expectations reproduced.

Not covered by the bundle

What needs more than Python

The bundle doesn't include OWL 2 DL reasoning or the Jena cross-check. The recorded run used Pellet via owlready2 0.51 and Apache Jena 6.2.0, and the two engines agreed with pySHACL on all nine cases. Regenerating the outputs needs the OntoGraph runtime, which isn't public yet. The bundle checks the published outputs, not the pipeline that produced them.

04 / Tonto 0.9.4

A cross-check, not a modelling authority

Tonto 0.9.4, NEMO's text DSL for OntoUML, was used as a cross-check. It is not the authority for these models, and no model was changed to satisfy it. OntoGraph provides an OntoUML-faithful Tonto conversion, ontograph-dsl-tonto, with dual verdicts: Tonto's own check, and OntoGraph's correction where Tonto diverges from published OntoUML/UFO. A Tonto round-trip of the nine projected graphs, run with the same binary as the retained acceptance run, produced identical gUFO on all nine cases. That test needs the private runtime and is not in the portable bundle.

Places where Tonto 0.9.4 diverges from published OntoUML/UFO, or where its tooling is incomplete, include:

  • «event» specialising «event». Tonto rejects this, so it rejects example 05 (SemiFinal and Final under Match). Published OntoUML allows an «event» class to specialise an «event» class, and that is how the upstream example is written.
  • An optional same-type sub-collection. Tonto's sub-collection-multiplicity and parthood-descends-forever rules cannot both be satisfied for a collective with an optional sub-collection of its own type, so a fleet-within-a-fleet as in example 02 cannot pass tonto check.
  • A partition is not read from a generalization set's categorizer. Tonto detects a partition only from @instantiation and (instanceOf …), so it can miss the invalid-07 pitfall when the categorizer is written only as a generalization-set categorizer.
  • No OntoUML JSON export in the 0.9.4 CLI, and tonto ast exits 0 on some inputs that do not parse, printing a recovered empty tree.

Where Tonto is right, we say so. Its rejection of invalid 07 under genset-contradicts-instantiation matches UML 2.5.1 and Carvalho, Almeida and Guizzardi (CAiSE 2016): a generalization set that is not disjoint is an overlapping one, and combining that with an «instantiation» upper bound of 1 is invalid. We had earlier read isDisjoint as merely leaving disjointness unasserted, and we have withdrawn that objection. Tonto is also right to require a single participant on a «participational» portion, in line with UFO-B: gufo:Participation has exactly one participant.

The gap that remains on our side is that OntoGraph's own UFO rules do not yet check that Table 3 combination from the 2016 paper. That is an OntoGraph rule to add, not a Tonto issue.

06 / Earlier Turtle check

A separate Turtle admit-and-regenerate result, not the headline

On 9 October 2026 we ran the nine upstream Turtle files themselves through OntoGraph: admit, store, and regenerate. Every assertion came back unchanged (808 / 808), the seven valid files still conformed to gufoshapes, and the two invalid files failed with exactly 2 and 5 violations, matching the upstream files. OWL 2 DL consistency was 9 / 9, including both invalid files. That result is a Turtle round-trip. It is not evidence that OntoGraph projects OntoUML into gUFO, and it is not the result this page now leads with.

The portable re-check for that earlier run is unchanged: gufo-examples-check.zip (76 KB), with README, check.py and expected.json. Recorded evidence remains under the 9 October 2026 verification. That bundle uses gufoshapes from the separate gufoshapes repository at commit b95e14b. The OntoUML-to-gUFO bundle uses examples/common/gufoshapes.ttl from the gUFO pin f412254, which is the file the retained projection run used.

08 / Limits

What this edition does not claim

  • The OntoGraph engine is private. The portable bundle checks published outputs against gufoshapes; it does not rerun the projection.
  • There is no independent human ontologist review yet. Self-review of the classified differences is not a substitute for one.
  • No claim is made of parity with the official OntoUML validator, the OntoUML server, or the Visual Paradigm plugin's "Export to gUFO".
  • The two invalid cases are the pitfalls that ship with the upstream examples. Relators, qualities, events and situations still have no negative acceptance case in this suite. The ordering extension of example 05 is ours, and is labelled as such.
09 / Questions

Where a review would help most

  1. The invalid-07 encoding, the MatchParticipation class, and the range of :participatedInMatch. These are the three pending questions under differences.
  2. Time-qualified grounding. When a role holds only while a relator exists, should a gUFO projection express that through the relator's own begin and end points, through situations, or through something else?
  3. Identity and dependence in partial snapshots. If a graph is a partial snapshot, for example an appointment whose organisation simply isn't recorded, should a UFO-grounded system report a violation (closed world) or an unknown participant (open world)?

Related work

This work builds on UFO (Guizzardi, Ontological Foundations for Structural Conceptual Models, 2005; Guizzardi et al., UFO: Unified Foundational Ontology, Applied Ontology, 2022) and on OntoUML as the language for UFO-compliant models. The target is gUFO (Almeida, Guizzardi, Sales and Fonseca, gUFO: A Gentle Foundational Ontology for Semantic Web Knowledge Graphs, 2026), validated with gufoshapes. The closest existing tool is the OntoUML-to-gUFO transformation in the OntoUML server, which the Visual Paradigm plugin uses for "Export to gUFO". OntoGraph doesn't replace it. Carvalho, Almeida and Guizzardi, CAiSE 2016, is the published basis for treating a non-disjoint generalization set as overlapping, which is why we withdrew our earlier objection to Tonto on that point.

10 / OntoGraph's own worked case

Research appointments: modelling under revision

Separately from the gUFO usage examples, we built a small case of our own about people, organisations and research appointments, to test how OntoGraph keeps identities connected across views. Its evidence is recorded, but the model has known problems, and we'll revise it before asking for feedback on it.

Known issues
  • The «role» Researcher isn't connected to any mediation. Appointment mediates Person and Organization directly, whereas gUFO's relators example mediates the roles Employee and Employer.
  • Time uses a custom comp:begin/comp:end pair instead of gUFO's own properties, such as gufo:hasBeginPointInXSDDateTimeStamp.
  • The appointment data is contrived: intervals of two to three hours, a leap day and a +14:00 offset, chosen to test edge cases rather than to look realistic.
  • The Mass quality and the Seminar event are in the model without any explanation of why they are there.
  • The generated graph types Appointment and Mass as gufo:EndurantType, as subclasses of gufo:Relator and gufo:Quality. That choice hasn't been justified.
