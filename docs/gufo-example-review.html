gUFO example review

Giancarlo Guizzardi recommended the gUFO usage examples as a reference for reviewing OntoGraph. We reproduced the reference tests, integrated eight related implementation branches, and exercised the combined product locally.

We can demonstrate a bounded, source-accountable workflow with actual reasoning and constraint results. We cannot yet claim comprehensive OntoUML/gUFO transformation or conformance. The evidence below identifies what ran, what passed and what remains unsupported.

Results you can inspect​

CheckObserved local result
Source against research harvest10/10 selected files are byte-identical: ontology, seven positive examples and two invalid examples.
Original upstream Pellet/pySHACL suite26/26 tests passed.
Combined Windows Rust suite2,146 passed, zero failed; optional external-engine tests are recorded separately in the local-checks evidence.
Python / focused JavaScript suites240 Python tests and 15 JavaScript tests passed.
Installed HermiT, source-local graphsNine consistent results; all nine CLI/API comparisons matched. Both deliberately invalid examples remain OWL-consistent.
Installed HermiT, full vocabulary with unsupported datatypes ignored18 actual consistency/entailment operations; all 18 results persisted and reloaded. This explicitly weakens datatype reasoning.
Installed JenaNine SHACL checks: seven conformant, two expected nonconformant. Nine SPARQL operations. All 18 results persisted, reloaded and compared; CLI/API parity verified.
Four semantic workflowsMereology, qualities/relators, events/situations and higher-order types executed through the installed CLI. Their reviewed projections retain unsupported residue.
Catalog34 artifacts, including two vocabularies, persisted/reloaded; profile-scoped reimport verified; three VPP limitations retained.
Validator compatibilityAll 366 assumption-specific rows processed. All remain explicit capability gaps across 13 unimplemented/unadopted rules.

These are different kinds of evidence. The four reviewed semantic workflows do not constitute an arbitrary Turtle/OntoUML transformer. The Node aggregate verifies provenance and deterministic persistence; the installed HermiT/Jena reports separately prove external-tool execution.

The two SHACL-invalid examples being OWL-consistent is an expected and useful result: consistency alone does not detect every misuse of the typing patterns. The upstream and installed SHACL lanes retain separately identified graphs and shapes; matching outcomes do not establish graph or engine equivalence.

Download the proof​

The evidence index records file sizes and SHA-256 digests. These files are public and need no access to the private product repository:

  • Combined installed proof and remaining capability gaps.
  • Exact source, binary identity, local test results and platform limitations.
  • Full-vocabulary HermiT operations and explicit assumptions with verification.
  • Installed Jena requests, results and persistence evidence with verification.
  • Catalog identity, reload and reimport verification.
  • Source/harvest comparison and 26 upstream results.
  • Invalid endurant-types report and invalid higher-order-types report.

The integrated candidate is aabd3c61b5bff159b4d908ef7e919897e841a9f6. The initial product baseline was c513459cc7179cf8b0af00b3c112300a04a08ea7; upstream gUFO is pinned at f4122544133544eb4c6c467ba316302ab20b754a. Evidence references identify the actual tested candidate independently of the later documentation publication commit.

What remains to be done​

Remaining capabilityRequired next work
Full gUFO datatype reasoningSpecify, pin and qualify a product reasoner adapter that supports xsd:date. Current HermiT rejects it in the full import closure; ignoring unsupported datatypes is a weaker assumption. The successful upstream Pellet baseline is not a product Pellet adapter.
General semantic transformationExtend the reviewed mappings to unrestricted inputs only with explicit contracts and independent positive/adverse examples. Compare generated graphs semantically; keep temporal/historical dependence and other unmapped constructs as residue until supported.
OntoUML Validator rulesAdopt and implement each of the 13 rules under explicit open-world/closed-world assumptions, then rerun the 366 rows against their expected results. Inventory coverage is not rule support.
Cross-format equivalenceImplement semantic parsing/comparison where claimed. Byte-preserving VPP/catalog storage does not prove JSON/Turtle/VPP equivalence.
Local Linux qualificationComplete an installed Linux run of this integrated candidate. The attempted local container build stalled and Docker stopped answering status requests; no Linux pass is claimed.

The owner requested local testing and waived GitHub CI as a gate for this review. No hosted CI result is used as proof. This decision does not remove the semantic or platform limitations above.

Repository collaborators can inspect the integration PR, review issue, interoperability plan and installed acceptance issue. The latter retains the wider acceptance scope.

Reproduce the reference comparison​

The pinned upstream suite and instructions are public. The recorded environment uses Python 3.11.14, Java 17, Owlready2 0.46, RDFLib 7.6.0, pySHACL 0.40.1 and pytest 9.1.1. Run test_examples.py and expect 26 passing tests. Installation is separate from test execution.

The independent Jena baseline uses Apache Jena 6.2.0 and Java 21.0.7, each example as its data graph, and standalone shapes at the pinned revision. The operation is shacl validate --shapes shapes.ttl --data example.ttl. Compare outcomes and graph contents; raw RDF serialization order may vary.

This report is suitable for reviewing the bounded outcomes and asking for feedback on the remaining semantic work. It is not comprehensive conformance, certification or a release claim. No message has been sent to Giancarlo.
